Fable UI gives an AI agent a design system it can speak. Instead of answering with a wall of Markdown, the model calls one tool, `render_ui`, with a short list of **blocks** — an article, a sortable table, a chart, a form, an editable email, a gallery — and your app renders them with real components while the answer streams.

<BlockPreview name="columns" />

## How it works

1. **The model writes JSON, not code.** `render_ui` takes a list of blocks from a fixed catalog. Every field has a type and a size limit.
2. **Fable validates each block on its own.** A malformed block is skipped; the rest of the answer still renders.
3. **Blocks stream in place.** Finished blocks appear as soon as they close. The block still being written either streams its text or shows a skeleton that holds its space.
4. **Interactions go through you.** Buttons can send a follow-up message, copy text, download a file, open a vetted link, or call an action your app registered. Nothing else can run.

## What you get

- **24 blocks and 3 layouts** — text, data, media, interactive drafts and forms, plus columns, sections and tabs.
- **A chat shell** (`FableChat`) for new apps, or a single renderer (`FableToolPart`) for an existing `useChat` UI.
- **A system prompt** that teaches composition: lead with the answer, choose a format per idea, end with next steps.
- **Six theme presets** that are plain shadcn CSS variables, plus support for any theme from the shadcn customizer.
- **Agent guides** you can paste into Claude Code, Cursor or Codex to install and verify everything.

## Compared with GPT-6 Intelligent UI

ChatGPT's Intelligent UI showed what model-composed interfaces can feel like. Fable takes the same idea into your own product: your model provider, your components, your theme, your actions. It also avoids executing model-written code entirely, so there is no sandbox to maintain. Read [Architecture](/docs/architecture) for the full comparison.
